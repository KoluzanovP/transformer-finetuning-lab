# Деплой через веб-интерфейс Timeweb Cloud (Apps + GitHub)

Этот путь — **без сервера и SSH**: вы подключаете GitHub-репозиторий в разделе
**«Приложения» (Apps)**, и Timeweb сам собирает и запускает контейнеры, а при
каждом `git push` — передеплоивает.

Разворачиваем **три вещи**: базу данных, приложение **API** и приложение **веб**.
Приложения получают отдельные адреса (домены), поэтому фронт обращается к API по
его публичному URL — это уже предусмотрено (CORS + переменная `NEXT_PUBLIC_API_URL`).

> Репозиторий: `koluzanovp/edu-platform`. Проект лежит в корне репозитория,
> поэтому **контекст сборки = корень**, а Dockerfile указываем как `apps/api/Dockerfile`
> и `apps/web/Dockerfile`.

---

## Шаг 1. База данных (управляемая PostgreSQL)
Приложения Apps не хранят БД внутри — создаём отдельно.
1. Панель Timeweb Cloud → **Базы данных → Создать → PostgreSQL 16**.
2. После создания откройте БД и скопируйте **строку подключения** вида
   `postgresql://user:pass@host:5432/dbname` (обычно нужно добавить `?sslmode=require`).
   Это будущий `DATABASE_URL`.

## Шаг 2. (Рекомендуется) S3-хранилище для медиа
В PaaS файловая система контейнера временная — загруженные видео/фото при
передеплое пропадут. Поэтому храните медиа в S3.
1. Панель → **S3-хранилище → Создать бакет**, сделайте его публичным на чтение.
2. Получите **Access Key / Secret Key**, запомните **endpoint** (напр.
   `https://s3.timeweb.cloud`), **регион** и **публичный URL** бакета.

## Шаг 3. Подключить GitHub
1. Панель → **Приложения → Создать приложение**.
2. Источник — **GitHub**. Авторизуйте приложение Timeweb в GitHub и дайте доступ к
   репозиторию `koluzanovp/edu-platform`.

## Шаг 4. Приложение №1 — API (создаём первым)
1. Создать приложение → репозиторий `edu-platform`, ветка **main**.
2. Тип сборки — **Dockerfile**.
   - **Путь к Dockerfile:** `apps/api/Dockerfile`
   - **Контекст сборки / корневая папка:** `/` (корень репозитория)
   - **Порт приложения:** `4000`
   - **Health check путь:** `/api/health`
3. **Переменные окружения** (Environment):
   ```
   NODE_ENV=production
   DATABASE_URL=<строка из шага 1, со sslmode=require>
   JWT_ACCESS_SECRET=<случайные 32+ символа>
   JWT_REFRESH_SECRET=<другие случайные 32+ символа>
   STORAGE_DRIVER=S3
   S3_ENDPOINT=https://s3.timeweb.cloud
   S3_REGION=ru-1
   S3_BUCKET=<имя бакета>
   S3_ACCESS_KEY_ID=<ключ>
   S3_SECRET_ACCESS_KEY=<секрет>
   S3_PUBLIC_BASE_URL=<публичный URL бакета>
   BOOTSTRAP_ADMIN_EMAIL=admin@ваш-домен.ru
   BOOTSTRAP_ADMIN_PASSWORD=<надёжный пароль ≥8>
   WEB_ORIGIN=https://<адрес будущего веб-приложения>
   ```
   (Секреты удобно сгенерировать локально: `openssl rand -hex 32`.)
   `WEB_ORIGIN` пока можно оставить временным — уточним на шаге 6.
4. Задеплойте. Миграции БД применятся автоматически при старте, а из
   `BOOTSTRAP_ADMIN_*` создастся аккаунт автора платформы.
5. Скопируйте выданный **URL API**, например `https://edu-api-xxxx.twc1.net`.
   Проверьте: откройте `<URL API>/api/health` — должно быть `{"status":"ok"}`.

## Шаг 5. Приложение №2 — веб (Next.js)
1. Создать приложение → тот же репозиторий, ветка **main**, тип — **Dockerfile**.
   - **Путь к Dockerfile:** `apps/web/Dockerfile`
   - **Контекст сборки / корневая папка:** `/`
   - **Порт приложения:** `3000`
2. **Переменная сборки** (Build argument / переменная, доступная при сборке):
   ```
   NEXT_PUBLIC_API_URL=<URL API из шага 4, например https://edu-api-xxxx.twc1.net>
   ```
   ⚠️ Важно: это значение «запекается» в фронт **на этапе сборки**, поэтому его
   нужно задать как переменную сборки ДО первого билда.
3. Задеплойте. Скопируйте **URL веб-приложения**, например
   `https://edu-web-yyyy.twc1.net`.

## Шаг 6. Связать фронт и API (CORS)
1. Вернитесь в приложение **API** → переменные окружения.
2. Пропишите `WEB_ORIGIN=https://edu-web-yyyy.twc1.net` (точный адрес веб-приложения).
3. (Если планируете OAuth) добавьте:
   ```
   OAUTH_CALLBACK_BASE=https://edu-api-xxxx.twc1.net
   OAUTH_SUCCESS_REDIRECT=https://edu-web-yyyy.twc1.net/oauth/callback
   ```
4. Передеплойте API (кнопка Redeploy).

## Шаг 7. Свой домен
1. В приложении **веб** → раздел «Домены» → привяжите `edu.ваш-домен.ru`
   (добавьте CNAME/A по подсказке панели). Timeweb выпустит SSL автоматически.
2. Обновите переменные:
   - веб (build): `NEXT_PUBLIC_API_URL` — оставьте URL API (или заведите поддомен
     `api.ваш-домен.ru` для API-приложения и укажите его);
   - API: `WEB_ORIGIN=https://edu.ваш-домен.ru`.
3. Передеплойте оба приложения.

## Шаг 8. Первый вход и наполнение
- Откройте адрес веб-приложения и войдите как **автор** (email/пароль из
  `BOOTSTRAP_ADMIN_*`). После входа переменные `BOOTSTRAP_ADMIN_*` можно удалить.
- Готовые курсы математики (по желанию) заливаются **сидами**. В Apps нет консоли
  контейнера, поэтому запустите сиды с любого компьютера с Node 20 и pnpm,
  указав строку подключения к вашей БД (шаг 1):
  ```bash
  git clone https://github.com/koluzanovp/edu-platform.git && cd edu-platform
  pnpm install && pnpm --filter @edu/shared build
  cd apps/api && pnpm exec prisma generate
  DATABASE_URL='<строка подключения к БД Timeweb>' pnpm seed:math
  DATABASE_URL='<строка подключения к БД Timeweb>' pnpm seed:ege
  ```
  (Курсы можно так же собирать прямо в интерфейсе автора — сиды не обязательны.)

## Готово
При каждом `git push` в `main` Timeweb пересоберёт и передеплоит приложения,
а миграции применятся сами.

## Частые вопросы
- **Почему два приложения, а не одно?** Apps запускает один контейнер на приложение;
  у нас фронт и API — разные процессы. Они общаются по HTTP, cross-origin уже
  настроен (CORS + `NEXT_PUBLIC_API_URL`).
- **Медиа исчезли после передеплоя** — включите `STORAGE_DRIVER=S3` (шаг 2). На
  LOCAL диск в PaaS временный.
- **CORS-ошибка** — `WEB_ORIGIN` в API должен точно совпадать с адресом фронта
  (со `https://`). После изменения — Redeploy API.
- **Фронт стучится не туда** — `NEXT_PUBLIC_API_URL` задаётся как переменная
  СБОРКИ веб-приложения и требует пересборки после изменения.
- **Не могу войти автором** — задайте `BOOTSTRAP_ADMIN_EMAIL`/`BOOTSTRAP_ADMIN_PASSWORD`
  в API и передеплойте.

> Нужен вариант «всё на одном сервере одной командой» — см. `DEPLOY_TIMEWEB.md`.
