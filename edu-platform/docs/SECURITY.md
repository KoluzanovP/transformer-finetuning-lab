# Безопасность

Сводка реализованных мер. Цель — защита по умолчанию на всех уровнях.

## Аутентификация и сессии
- **Пароли** хешируются `bcrypt` (12 раундов). В открытом виде не хранятся и не логируются.
- **Политика пароля**: минимум 8 символов, обязательны буквы и цифры (валидация DTO).
- **JWT access** — короткоживущий (по умолчанию 15 мин), подписан отдельным секретом.
- **Refresh-токены** — случайные, в БД хранится только `sha256`-хэш (не сам токен).
- **Ротация refresh** при каждом обновлении: старый токен отзывается.
- **Детект повторного использования**: предъявление уже отозванного refresh-токена
  трактуется как компрометация — отзываются ВСЕ активные сессии пользователя.
- **Logout** отзывает refresh-токен.

## Авторизация (RBAC)
- Глобальные guard'ы: `JwtAuthGuard` (проверка токена) → `RolesGuard` (проверка ролей).
- Маршруты ограничены декоратором `@Roles(...)`; публичные — явно через `@Public()`.
- **Защита от эскалации привилегий**: публичная регистрация выдаёт только роли
  `STUDENT`/`PARENT`. Учителей, наставников и авторов заводит только автор
  платформы. Ограничение продублировано на уровне валидации и сервиса.
- Доменные проверки владения: автор правит только свои курсы; учитель проверяет
  ДЗ только закреплённых учеников; родитель видит только своих детей; участники
  чата/тикета — только свои переписки.

## Защита транспорта и заголовков
- **helmet**: `X-Frame-Options`, `X-Content-Type-Options: nosniff`,
  `Referrer-Policy`, `Cross-Origin-Resource-Policy` и др.; заголовок
  `X-Powered-By` скрыт.
- **CORS** ограничен списком доверенных origin'ов (`WEB_ORIGIN`), с credentials.
- **Фронтенд** (Next.js) отдаёт свои security-заголовки и скрывает `X-Powered-By`.

## Ввод и данные
- **Валидация** всех DTO (`class-validator`), `whitelist` + `forbidNonWhitelisted`:
  неизвестные поля отклоняются (защита от mass-assignment).
- **ORM Prisma** параметризует запросы — защита от SQL-инъекций.
- **Лимит тел** JSON/urlencoded — 1 МБ; загрузка файлов — отдельный multipart-лимит.

## Rate limiting
- Глобальный лимит `@nestjs/throttler` — 200 запросов/мин на IP.
- Ужесточённый лимит на `/auth/login` и `/auth/register` — 10/мин (анти-брутфорс).

## Загрузка файлов
- Проверка MIME-типа по заявленному виду медиа (IMAGE/VIDEO/AUDIO).
- Санитизация имени файла, генерируемый ключ хранения (без пути от пользователя).
- Ограничение размера; статика отдаётся с `index:false`.
- Для S3/R2 — presigned URL с коротким TTL (15 мин).

## Эксплуатация
- В `production` приложение **не стартует** с дефолтными/слабыми JWT-секретами.
- Каждое значимое действие пишется в аудит-лог (`AuditLog`) с актором и IP.
- Секреты — только через переменные окружения; `.env` в `.gitignore`.

## Проверки в тестах (e2e)
- Запрет эскалации роли при регистрации (`AUTHOR` → 400).
- Отклонение неизвестных полей тела (400).
- Ротация и запрет повторного использования refresh-токена (401).
- Отклонение слабого пароля (400).
- RBAC: ученик не создаёт курс (403); родитель не видит сводку автора (403).

## Дальнейшие шаги (ROADMAP)
- 2FA/TOTP для персонала, CAPTCHA на регистрации.
- Подписанные/приватные URL для медиа, антивирус-скан загрузок.
- Централизованные секреты (Vault), ротация ключей, WAF, аудит-экспорт.
